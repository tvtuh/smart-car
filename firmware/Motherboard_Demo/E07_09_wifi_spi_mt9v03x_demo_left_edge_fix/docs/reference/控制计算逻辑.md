**fw103-preview42：当前工程的控制计算逻辑**

本文对应 `smart_car/mdk/seekfree.uvproj`。使用同目录的 `打开工程.bat` 打开已安装的 C251 版 Keil；生成的烧录文件是 `smart_car/mdk/out_file/SEEKFREE.hex`。

控制数据依次经过：视觉中线 → 三行加权误差 → 转向 PD → 舵机角度与 PWM；目标速度 → 左右差速 → 电机 PWM。转向每处理完一帧图像计算一次，电机输出由 10ms 定时中断更新。

当前沿用压缩包原版的同步传图流程：每帧先完成视觉和控制，再调用逐飞 SDK 的 `seekfree_assistant_camera_send()`，发送返回后才进入下一轮主循环。发送使用 SDK 默认的 `wifi_spi_send_buffer` 回调；电机 10ms 定时中断仍独立运行。链路慢速检测、暂停上传及自动探测恢复也按压缩包原逻辑执行，具体见第 10 节。

本次撤掉连续丢线 0.3 秒计时锁停，原有按丢线帧数处理的逻辑继续生效。最新视觉、42/30/17 预瞄、转向及差速参数、无线串口和 WiFi/IP 设置均保留。

默认 42/30/17 时发一次 p，即变成 42/29/16；再发 P 回到 42/30/17。调节范围为 42/20/7～42/40/27，保持近、中、远顺序并避免越界。预瞄切换后的第一帧清除旧微分历史，避免仅因换采样行产生一次打角冲击，之后继续正常 PD。

回显示例：

```text
DRV TUNE row=42/30/17 slew100=400 kp100=30/20 kd100=55 lim10=180
DRV SET v=38 diff100=40 mode=0 cap=0 img=1 out=0 trim10=-25 inv=0 ringv=38 k=0
```

slew100、kp100、kd100、diff100 为对应值乘 100；lim10、trim10 为角度乘 10。out=1 表示电机输出已允许，k=1 表示舵机自检暂时接管。改参数立即生效，回显每次空闲轮询最多发送一条；有摄像头帧等待处理时先算控制，不发这些回显。若一直有图像积压，查询回显也会持续延后，参数本身已经应用。收到新一轮调参时合并为最新参数快照，不逐条重发旧值。

本次移除的串口入口：编码器反向/接口/插座切换 1、2、a、d、q、w、e、v、b；原 r 改为预瞄复位；推车计数 c、台架测速 t 和原速度调节 [、]；旧备用圆环策略 y、m/M、z、s、j/J；关闭的自动速度系数 5～8；日志周期 +、-。对应的大写别名也移除。原 p/P 已改为预瞄调节。底层编码器驱动、视觉圆环算法和旧备用固定打角算法保留。

**2. 每行如何得到偏差**

在普通有效行上，中心来自视觉模块的 `track_center[row]`，通常由左右边界平均得到。处理图像中心列为 47。底部受舵机遮挡的原第 59 行已排除，寻线从原第 58 行向上计算；白区后处理、十字和圆环使用同一个有效区域。自动阈值统计也不读取对应的原图底部 2 行。摄像头及 DMA 仍按 188×120 采集：

```text
center ≈ (left + right) / 2
row_error = 2 × (center - 47)
```

这里乘 2 是把下采样图上的偏移换回原图尺度，因此现有转向参数仍按原图像素量级使用。正误差表示目标中线在画面右侧。

圆环引导有效时，直接使用视觉模块给出的引导中线。普通行如果只有一侧边界跑出画面，会用另一侧边界加减历史半赛道宽度估算中心；两侧都不可用或宽度不合格，则该行不参加加权。历史半宽按 `新值=(7×旧值+本帧宽度/2)/8` 更新。

**3. 三行合成一个瞄点误差**

三行都有效时：

```text
aim = trunc((20×e_near + 30×e_mid + 60×e_far) / 110)
aim = limit(aim, -70, 70)
```

无效行的误差及其权重一起移除，再按剩余权重归一化。三行都无效时继续进入原有控制分支：存在双边丢失行则 `aim=0`，否则暂用上次瞄点；随后执行第 9 节的开口与丢线帧数处理。此时不再保持旧命令等待 300ms，也不执行计时锁停。

例如三行误差分别为 4、8、12，则加权值是 1040/110，整数截断后 `aim=9`。

**4. 转向 PD 如何计算**

转向使用视觉流水线的最终中线。本次按压缩包及用户选择将 TRACK_TEMPORAL_ENABLE 设为 1：先对左右边线做三帧时间中值，再执行最终平滑/贴边约束，随后 track_white_lane_guard 使用本帧连通白区校正，圆环补线最后经过本帧白区校验。PD 默认增益保持原值，预瞄仍为 42/30/17，最大转角仍为 ±18°。

时间中值阶段可以抑制孤立一帧的边线偏移，但后续白区校验会重新选取当前物理边界，因此不能承诺最终控制中线固定延迟一帧或必然消除抖动。完整流水线测试中，唯一白色赛道横移后，中值阶段保留旧坐标，白区校验后仍输出当前白区中线；当前画面全黑时，历史中线被清为无效。

微分项先做低通：

```text
D[k] = 0.7×D[k-1] + 0.3×(aim[k]-aim[k-1])
```

当前代码用每帧误差差值，没有除以帧间隔 dt，因此这是按图像帧工作的离散 PD。

比例系数按误差大小在软、硬两组增益间过渡：

```text
|aim| ≤ 8：      Kp = 0.20
8 < |aim| < 20： Kp = 0.20 + 0.10×(|aim|-8)/12
|aim| ≥ 20：     Kp = 0.30
steer = Kp×aim + 0.55×D
```

积分项默认关闭。转向可通过 `n` 命令取反；绝对角度小于 0.4° 时归零，最终控制命令限制为 ±18°。

接上面的例子，若上一帧 aim=8、上一帧 D=0，则本帧 D=0.3、Kp≈0.2083，得到 `steer≈2.04°`，再送往舵机。

**5. 舵机角度如何变成 PWM**

当前舵机反向开关为 1，微调偏置为 -2.5°，安装补偿为 +5°：

```text
目标舵机角度 = 90 - (steer - 2.5) + 5 = 97.5 - steer
```

因此逻辑转向 0° 对应舵机约 97.5°。方向正负由安装方向和反向开关共同决定。

角度变化每经过一个 10ms tick 最多允许 4°，单次调用最多变化 36°，随后执行软限幅 ±18°、硬限幅 ±18°以及绝对角度 55°～125°限制。36° 是从左满舵到右满舵的总跨度，最终打角仍是左右各 18°。

原来的单次 12° 上限使低帧率下从直行打到 18° 至少需要两次图像更新。现在，当距上次舵机调用已过 50ms，时间预算允许 20°，一次就能输出 18°；若只过 10ms，仍最多变化 4°。这里描述的是 PWM 命令，舵机机械运动速度不会因此无限提高，也没有提高 50Hz PWM 频率。

预瞄改为 42/30/17 后，画面第 22 行及以上已经出现弯道、原第 25 行仍为直道时，就会开始转向。软件样例中，远端中线右移 6 个处理像素，当帧约输出 +2.19°；左弯对称。提前了多少毫秒或多少厘米取决于车速、摄像头姿态和赛道，不能由图像行数直接换算。

```text
脉宽(ms) = 0.5 + 舵机角度/90
PWM占空比 = 脉宽 / 20ms       （50Hz）
```

例如 `steer=2.04°` 的目标角度约为 95.46°，脉宽约 1.561ms，占空比约 7.80%；实际输出还受缓变限制。

隔离时间中值阶段的复现中，直道预热后中线从 47 突变为 53，第一帧仍输出 47，持续第二帧后输出 53；最终白区校验可能在第一帧就把中线校回当前赛道。因此这一帧延迟不能直接当作整车转向延迟。50Hz PWM 的周期仍为 20ms，舵机机械速度和供电也会影响实车响应。

**6. 基础速度和圆环的关系**

当前固定速度模式开启，正常基础目标取 38。起步输出已释放且没有故障时，前 40 个输出已释放、无故障且目标速度为正的控制帧额外增加 14；之后恢复 38。中预瞄行存在有效圆环引导时，速度上限取 `s_ring_speed`，初值 38，可用 `l/L` 调节。

旧的“锁住直行瞄点 → 到指定行号固定打角 → 保持若干帧 → 逐渐交还转向”备用算法仍保留在关闭视觉补线时的分支中。当前 `RING_FIX_ENABLE=1`、`CAR_RING_ENABLE=0`，默认按视觉引导中线计算 PD。本次精简了这套旧备用策略的串口命令入口；`p/P` 已改为普通转向预瞄调节，`l/L` 仍用于当前有效的圆环速度上限。

如果将 `CAR_SPEED_FIXED_ENABLE` 改为 0，才会启用另一套基础速度规划：

```text
curve = min(80, abs(2×(e_far-e_mid)))
v = 58 - 1.00×curve
v 再按远端绝对误差超过 CAR_CURVE_EARLY_DEAD 的部分提前减速
```

这套自动规划当前没有生效。附加弯道限速由 `%` 单独控制，默认也关闭。

**7. 左右轮差速**

默认使用未归一化的差速方式：

```text
diff = trunc(0.4×steer)
v_left  = limit(v + diff, 0, 58)
v_right = limit(v - diff, 0, 58)
```

正 steer 对应右转，左轮目标更大。巡航 v=38、steer≈2.04° 时，0.4×2.04≈0.816，整数截断后 diff=0，因此左右目标都是 38。

`=` 命令可切换到归一化差速。这种方式用舵机已经输出的实际转角：

```text
ratio = limit(0.4×实际转角/38, -0.45, 0.45)
v_left  = v×(1+ratio)
v_right = v×(1-ratio)
```

若某轮超过 58，两轮按同一比例缩小，保留速度比。默认方式则直接把每轮分别限幅。

**8. 电机当前是开环 PWM**

`CAR_ENABLE_ENCODER=0` 时，10ms 中断中执行：

```text
目标PWM = limit(40×该轮目标速度数值, -5000, 5000)
```

PWM 以 10000 为满量程，所以 38 对应 1520，即 15.2%；52 对应 2080，即 20.8%。每个 10ms 周期，输出相对上次最多变化 200，即 2 个占空比百分点。

上述差速例子的左右轮目标都是 38，对应目标占空比均为 15.2%。实际车速由电池、负载、电机等共同决定，目前不会根据编码器读数自动纠偏。

若后续在配置文件中开启 `CAR_ENABLE_ENCODER=1`，才会用每 10ms 的编码器计数闭环：

```text
N_target = trunc(v_target × 15740 / 10000)
error = N_target - N_actual
I = limit(I + error, -2500, 2500)
PWM = limit(10×N_target + 6×error + I, -5000, 5000)
```

显示速度的换算为 `v_actual=trunc(N_actual×10000/15740)` cm/s。编码器的 15740 计数/米是当前配置值。

**9. 丢线和启动门**

连续丢线 0.3 秒计时、对应主循环检查及硬切 PWM 锁停均已撤掉。保留原有按帧数处理：普通控制下，无有效预瞄行，或三行原始双边都丢失且没有有效圆环引导时，累计 `s_open_frames`。

- 前 25 帧作为开口宽限，丢线计数保持 0，继续执行原有控制计算。
- 从第 26 帧开始累计 `s_lost_frames`，转向取上次命令的 0.70 倍；当前固定速度模式下基础目标仍取 38，之后照常经过起步助推、限速及差速计算。
- 当 `s_lost_frames > 80` 时，将速度目标置零。普通连续全丢线从计数为零开始，第 106 帧首次置零。电机经原有 PWM 输出逻辑减速，不是计时后立即硬切输出。
- 中线恢复后按原条件清零计数，正常控制可以自行恢复；没有增加必须发 `o` 才解锁的丢线停车状态。

上述阈值按控制帧数计算，实际持续时间随处理帧率变化。若摄像头完全不再来帧，则由原有电机视觉心跳处理，不依靠丢线帧计数。

中心或边界为 255/越界、左右顺序错误、两侧都丢失且没有有效圆环补线的行不参与加权。圆环有效补线允许继续控制，但最终中线仍须通过本帧白区验证；单边丢线且仍能可靠估算中线时，不作为三行全丢线处理。

原有摄像头心跳超时与启动门保留：正常控制更新时刷新约 500ms 的心跳；同步传图前 `motor_heartbeat_link_guard()` 临时刷新为 1500ms，以沿用原版对阻塞链路的处理。上电输出默认关闭，视觉初始化和 5s 起步门结束后，发 `o` 释放电机输出。

**10. 当前同步传图方式**

图像发送位于当帧视觉、控制计算之后，直接调用 SDK 原版 `seekfree_assistant_camera_send()`，使用 `wifi_spi_send_buffer` 回调。处理及上传尺寸仍为 94×59。默认 `CAR_TELEMETRY_EVERY=1`，视觉初始化成功、WiFi 图像功能启用且 `!` 开关允许时，每个处理帧按原逻辑同步传图。

传图占用主循环，返回后才继续下一轮图像处理。此处已恢复原 SDK 等待方式；已撤掉自定义上传模块、积压时 20ms 的发送间隔、5ms 单包等待和 30ms 整帧预算。摄像头 DMA 采集以及电机定时中断沿用当前驱动。

恢复的链路检测按发送窗口运行：

- 单次发送耗时达到 300ms，计为一次慢发送；这里的 300ms 是链路耗时阈值，与已删除的丢线计时无关。
- 每发送 6 张检查一次窗口；其中至少 2 张慢发送，则暂停图像和示波器上传。
- 暂停后每隔 5000ms 试发一张；试发耗时低于 300ms 就自动恢复，仍慢则继续暂停并等待下次探测。

这是耗时检测，不是逐包成功应答验证。原版发送函数返回后才统计耗时，窗口不能提前中断正在阻塞的 SDK 调用。已撤掉此前因半帧失败而永久停用上传的自定义状态。
