# 圆环识别逻辑（一份讲清楚：谁在判、判什么、我们加了什么、怎么调）

> 面向：想看"圆环到底是怎么认出来的"的人（含视觉组）。
> 对应固件：**fw49**（工作区 `E07_09_wifi_spi_mt9v03x_demo`，D: 真工程同步）。
> 相关代码：`code\ring_road.c` / `code\ring_road.h`（**视觉组的原始实现，主体一个字没改**）、
> `user\main.c`（每帧调用顺序 + 我们加的"弯道里跳过"开关）、`user\car_control.c`（我们那层：闸门 / 侧别纠错 / 进环时机）。

## 一、整条链路：一帧图像里圆环相关的处理顺序

```
main.c 每帧：
  1  image_threshold_calc(IMAGE_THRESHOLD_MODE)     二值化（MANUAL 150）
  2  image_gray_copy(image_copy[0])                 灰度快照（算法吃这张，DMA 那张不能读）
  3  track_edge_process(PROC_IMAGE)                 种子生长法寻线 -> track_left/right/center/lost
  4  cross_road_process(PROC_IMAGE)                 十字识别 + 补线
  4.5 ring_road_process(PROC_IMAGE)   ← 圆环识别（【我们可以选择不叫它】，见第四节）
  5  track_line_smooth() / track_pin_lost_edges()   丢线插值、贴边
  6  track_temporal_filter()   【已开】             帧间 3 帧中值（治"线一帧一个样"）
  7  car_control_update()                           我们那层：闸门 / 测侧别 / 排进环时序 / 打角 / 速度
```

**关键分工**：`ring_road.c` 只负责 **①识别（这是不是环、在左还是在右）** 和 **②补线（把入口侧那条断掉的边线补出来）**；
**什么时候打角进环、往哪边打、打多少** 全在 `car_control.c`（我们这层）。

## 二、视觉组怎么认（`code\ring_road.c`，原文逻辑）

### 2.1 主判据：**"一边张开 + 对面是直道"**

| # | 条件 | 参数（`ring_road.h`） | 说明 |
|---|---|---|---|
| 1 | **对面那条边是连续直道** | `RING_STRAIGHT_LOST_MAX` **10**（这段里对面最多丢 10 行）<br>`RING_STRAIGHT_DEV_MAX` **6**（**偏差中位数**上限，像素）<br>`RING_STRAIGHT_MIN_PT` **12**（拟合至少 12 个有效点） | 取行范围 `RING_STRAIGHT_Y1..Y2` = `H*3/5`..`H-1`（靠近车身那一段）。<br>**用中位数不用最大值**：边界数组里偶尔有几行是离群点（种子行误差 / 跳变），实测最大偏差能被拉到 58 像素，而肉眼看那条线是直的 —— 中位数就只剩 2 像素 |
| 2 | **入口这一侧有一段足够长的连续丢线** | `RING_OPEN_LOST_MIN` **25** 行 | 实测右环入口丢 43~56 行 |
| 3 | **这段行范围里对面基本不丢线** | `RING_OPPO_LOST_MAX` **8**<br>`RING_OPPO_RUN_MAX` **15**（对面自己也不许有 >15 行的连续丢线段） | **这是圆环和十字的分水岭**：十字的横杠把左右**同时**盖住，圆环只有一侧张开 |
| 4 | （备用）入口侧边界的**突变拐点** | `RING_JUMP` **8** 像素 / `RING_JUMP_ROWS` **6** 行 | 文章的"方法一"。实测那个 20 多像素的突变经常**正好落在丢线行上**，所以允许跨过丢线行去比 |

扫描范围：`RING_SCAN_NEAR` = `H-6`（车头附近）到 `RING_SCAN_FAR` = `H/4`（远处）。

### 2.2 第二组判据：**环内特征行**（文章的"方法二"）

| 特征 | 参数 | 含义 |
|---|---|---|
| **全白行** | `RING_WHITE_MIN` **170**（一行 188 个点里白点 ≥170） | 环内那片白路面露出来了 |
| **黑白跳变行** | `RING_TRANS_MIN` **2**（一行里白↔黑交界 ≥2 次） | 环内岛（蓝底）的边界 |
| 扫描范围 | `RING_FEATURE_ROW1` = `H/6` 到 `RING_FEATURE_ROW2` = `H*3/5` | 图像上半部分 |

结果放进 `ring_white_row` / `ring_trans_row`（0 = 没找到）。

> **识别条件 = 对面直道 且 有拐点/长丢线 且（有全白行 或 有跳变行）**（他们文档里写的就是这句）。

### 2.3 状态机（`ring_state`）

| 值 | 状态 | 推进条件 | 我们这层的动作 |
|---|---|---|---|
| 0 | `NONE` 不在环 | 上面的识别条件**连续 `RING_CONFIRM_FRAME`(2) 帧**成立 | 判断要不要信它（闸门） |
| 1 | `FIND` 识别到入口 | 入口侧丢线 **≥ `RING_IN_LOST_MIN`(35)** 行 | **仍然直行**（不改方向） |
| 2 | `IN` 正在进环 | 出现环内特征（全白行 / 跳变行） | **仍然直行** |
| 3 | `INSIDE` 环内 | 入口侧丢线 **≤ `RING_OUT_LOST_MAX`(12)** | 进环 / 交还 |
| 4 | `OUT` 正在出环 | 两侧丢线都恢复 → 回 0 | —— |

两道保护：`RING_FIND_FAIL_MAX` **60** 帧（状态 1 里一直等不到"张开" → 判定入口是假的，复位重来）、
`RING_STATE_TIMEOUT` **200** 帧（任何状态卡死太久强制复位）。

> ⚠️ **注意**：车一开过**第二个路口**，入口侧丢线掉到 12 以下 → **他们自己的状态机会判"出环"**，`ring_flag` 随时会变 0。
> 所以我们这层的进环序列一旦开始就**自己撑住**（`s_rp_phase`），不再依赖 `ring_type`。

### 2.4 开口的两个拐点（这是"两个路口"的来源）

```
ring_open_row1  = a  = 开口的【近端】行  = 第一个路口   （离车近，先遇到）
ring_open_row2  = b  = 开口的【远端】行  = 第二个路口   （要在这里打角进环）
ring_corner_row = a  （补线的起点行）    ring_corner_col = 那一行的列
```

**行号越大 = 离车越近**（row 0 = 最远，`H-1` = 车头）。

### 2.5 补线（`ring_fix_side`）

- 状态 1/2：把入口侧那条边线补成**朝环内倾斜**的斜线（`RING_IN_SLOPE` **0.5** 像素/行，上限 `RING_IN_BIAS_MAX` **30** 像素）
  → 本意是"让车平稳转进去"，**但它就是"看到开口就提前往环里带"的元凶**，所以我们直行阶段要把瞄点抢过来；
- 状态 3（环内）：不补（环内白区就是路面，正常跟线能走）；
- 状态 4（出环）：补成竖直（斜率 0）；
- 补线是相对**对面那条可靠边线 + 赛道宽度**来补的，宽度用**拐点以下那段直道**对"宽度 vs 行号"做线性拟合得到（前视梯形），**补出来的值出画面就不补**（第一版没这个约束，边界被顶到 187 列，车往环外冲）。

### 2.6 侧别是怎么定的（**"左环被打成右环"的根源**）

```c
if(track_left_lost_count >= track_right_lost_count) {
    先试 ring_try_side(1, 1)  -> 成功: ring_type = LEFT
    再试 ring_try_side(0, 0)  -> 成功: ring_type = RIGHT     // ① 失败后退到另一侧
} else { 先试右边 ... }
```

**先试"丢线多的一侧"，失败后允许退到另一侧。** 左环时如果左边那次没过（远端拐点看不见 / 直线度没过 / 对面丢线超限），
它会退到右边试，右边只要凑巧也有一段丢线，就会把**左环报成右环** → 他们的补线也往右补 → 车往右打。
`ring_fail` 会记下失败原因（`-1x` 对面不直 / `-2` 没张开 / `-3` 像十字）。

## 三、这面判据有什么天生的漏洞

| 漏洞 | 为什么 |
|---|---|
| **"一侧连续丢线 ≥25 行 + 对面是直道" 在弯道里也成立** | 弯道里**外侧边线跑出画面**是物理限制（他们文档里也写了），一丢就是几十行，对面（内侧）还是直的 → 判据原封不动地满足 |
| **二值化/灯光把某一侧整段吃掉** | 同样凑出"一侧长丢线 + 对面直" |
| **补线会跟着误报走** | 一识别到"圆环"，`ring_fix_side` 就把中线往它认为的环内推（最多 30 像素）；弯道里误报时那个"环内"正好是**弯外** → 车被推着冲出弯道 |
| **侧别可能报反** | 见 2.6 |

**实车两个现象就是这么来的**："看到什么都觉得是圆环"（弯道里误报 + 补线推偏）和"左环也往右打"（侧别报反）。

## 四、我们加的三道防线（`user\main.c` + `user\car_control.c`，**没改他们的算法**）

### 4.1 弯道里**不叫**圆环模块（`main.c`，闸门档位 ≥1 时）

```c
if(0 != car_ring_module_ok()) { ring_road_process(PROC_IMAGE); }
else { ring_flag = 0; ring_type = RING_TYPE_NONE; ring_state = RING_STATE_NONE; }   /* 顺手清状态，免得出了弯还用弯里那次的判断 */
```

`car_ring_module_ok()` 看的是"弯道程度的**快衰减峰值**"`s_curve_peak`：

- 判据一：`s_curve_peak > CAR_RING_MOD_CURVE_MAX`(**24**) → **不叫它**（连补线都不会跑）；
- 阈值**故意比"接受阈值"宽**（24 对 12）：太严会把**紧跟在弯道后面**的真圆环也漏掉；
- 12~24 这一段就算它误报，我们也**不会进环**（闸门挡着），而且瞄点锁在直行基准上（4.3），它的补线带不动车。

### 4.2 可信度闸门（`car_control.c`，`s_rp_gate_on`，在线按 **`s`** 切 0/1/2）

识别到圆环的那一帧，逐条检查：

| 档 | 条件 |
|---|---|
| **0** | 关（报了就信 = 老行为） |
| **1** | ① 识别那一刻**在直道上**（`s_curve_peak ≤ CAR_RING_GATE_CURVE_MAX` **12**；在弯里只认"视觉组已经走到 INSIDE/OUT"这种强证据）<br>② **开口有界**：开口远端还得能看到 ≥ `CAR_RING_GATE_MIN_ABOVE`(**8**) 行边线 = "第二个路口看得见"（外侧线跑出画面时丢线会一直顶到画面最上面，这条过不了）<br>③ **开口够长**：入口侧丢线 ≥ `CAR_RING_GATE_MIN_OPEN`(**20**) 行 |
| **2** | 再加 ④ **视觉组自己确认过环内**：`ring_state` 到过 `INSIDE(3)/OUT(4)`，**或** 全白行 **和** 跳变行同时找到（原来只要有全白行就算，直道上地板有块白斑就能骗过去） |

**闸门不过 = 当没看见**：不进环、不打角，而且**瞄点锁成直行基准**（4.3）。`gfail` 记累计挡掉几次。

### 4.3 瞄点锁定（治画龙，`s_rp_aim_lock` / `s_rp_aim_hold`）

- **直行阶段**（信了、正在等第二个路口）：瞄点 = **识别前那一帧的"干净"瞄点**（`s_rp_aim_pre`，只在没识别到圆环时更新）→ 车按原来那条直道直着走，**他们的补线完全不参与**；
- **闸门没过**：同样锁（但**只在确实在直道上时才锁** —— 弯道里锁瞄点等于不让车转弯，更危险）；
- 兜底：直行阶段里弯道程度连续 `CAR_RING_ABORT_N`(**6**) 帧超 `CAR_RING_ABORT_CURVE`(**45**) → 判定误判，**立刻放开瞄点**。

### 4.4 侧别自己判 + 标签纠错

- **自己判**：`入口侧 = 哪一侧"最长连续丢线段"更长`（相差 ≥ `CAR_RING_SIDE_MARGIN`(**6**) 行才算；两边差不多才回退用 `ring_type`）。
  真环实测：环那一侧 43~56 行、另一侧 4~9 行，差得很开。
- **标签纠错**：我们判的侧和他们 `ring_type` 不一致，且特征明确（本侧连续丢线 ≥ `CAR_RING_LABEL_RUN_MIN`(**25**) 行、另一侧 ≤ `CAR_RING_LABEL_OPPO_RUN_MAX`(**12**) 行）
  → **直接把 `ring_type` 改成对的**，让他们的补线和状态机也走对的那一侧。`lfix` 记改过几次。
- 方向：**环在右边往右打、左边往左打**（`CAR_RING_DIR_SIGN`，在线 `z` 取反）。

### 4.5 进环时机 = **第二个路口**（不是看到张开就进）

| 阶段 `s_rp_phase` | 什么时候 | 我们做什么 |
|---|---|---|
| **1 直行** | 识别到 → 开口走到车头 | 瞄点锁直行基准；速度压到环内速度 |
| **2 进环** | 入口侧**最靠前的丢线行 ≥ `CAR_RING_ENTER_ROW`(100)** 或 **丢线行数 ≤ `CAR_RING_OPEN_GONE_LOST`(6)**，连续 `CAR_RING_ENTER_CONFIRM`(2) 帧 | `steer = ±CAR_RING_STEER_INSIDE`(12°) 固定打角，持续 `CAR_RING_ENTER_FRAMES`(30) 帧 |
| **3 交还** | 进环打角打完 | `CAR_RING_OUT_HOLD`(8) 帧内把打角还给跟线，**给完彻底放手**（出环不归我们管，车自己继续跑） |
| 兜底 | 直行阶段超 `CAR_RING_STRAIGHT_MAX`(150) 帧还没等到 | 放弃：当没识别到，继续直行（**绝不乱打角**） |

**为什么用丢线行判"到第二个路口"**：row 0 最远、119 车头；某一侧"最靠前的丢线行"越大 = 那一侧的开口离车头越近。
开口两个拐点都过去以后，要么只剩车头附近一小段丢线（`r_first ≥ 100`），要么整段丢线都出画面了（`r_lost ≤ 6`）。
这个判据对"开口是一整段"和"开口分成两段"两种赛道都成立 —— 认的是**最后一个开口的远端**。

## 七、常见现象 → 定位 → 怎么调

| 现象 | 先看 | 处理 |
|---|---|---|
| **到处都报圆环** | `CT` 的 `lost=L/R`、`lf/rf` 在**直道上**是不是就很大 | 大 → 是**二值化/灯光**问题（改 `IMAGE_THRESHOLD_MODE` = `NEAR_REF`，或重标 `IMAGE_THRESHOLD_MANUAL`）；不大 → 看 `?` 的 `gfail`（涨 = 闸门在挡，正常；不涨而 `ring≠0` = 闸门放行了，把 `orow/owhite/cv` 发我） |
| **圆环漏认** | `mskp` 涨得快 = 车老在弯里跑 | 把 `CAR_RING_MOD_CURVE_MAX` 放大；`gfail` 涨就按 `s` 降到 1 档 |
| **进早了**（第一个路口就拐） | `rph` 在开口还没到车头就变 2 | 按 **`p`** 降 `CAR_RING_ENTER_ROW`（每次 4 行） |
| **进晚了**（压到环外沿） | 同上 | 按 **`P`** 升 |
| **进不去 / 转不够** | 进环那几帧 `steer` 不够 | 按 **`J`** 加帧数、**`M`** 加打角 |
| **转过头 / 擦内圈** | 同上 | 按 **`j`** / **`m`** |
| **左环往右打** | `otype` vs `oside` | 不一致 = 标签错（fw47d 已自动纠错，看 `lfix` 涨没涨）；仍反就按 **`z`** |
