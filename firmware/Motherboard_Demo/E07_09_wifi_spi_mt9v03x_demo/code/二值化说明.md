# 赛道图像二值化说明

> ## ⚠️ 关于 `IMAGE_THRESHOLD_MANUAL` 的重要说明
>
> **当前值 = 150（现场标定值）。**
>
> **不要拿示波器 ch2（大津法阈值）直接当固定阈值用。**
> ch2 在同一个场地会在 **159~182** 之间浮动，因为它随画面里赛道/背景的占比变化 ——
> 换个视角、画面里多一个环岛，它就会变。它只适合用来**观察光线有没有整体变化**，
> 不适合当标定值。
>
> 曾经有一版按某一帧的 ch2=182 把手动阈值从 150 改成了 180，那是错的，已经改回 150。
>
> **判断阈值合不合适只看图像本身**：
> - 背景大片变白 → 阈值偏低
> - 赛道被吃掉变黑 → 阈值偏高

参考文章：[智能车图像处理(一)阈值处理](https://blog.csdn.net/weixin_50567482/article/details/119322251)

## 二、算法流程

1. **求全局阈值**：对一幅灰度图像求出能把赛道（白）和背景（蓝）分开的灰度跳变阈值。
   - **迭代法** `image_threshold_iteration()`：按文章思路，先给阈值 T 一个初值，用 T 把像素分成
     两组并分别求平均灰度 m0、m1，再取 `T = (m0 + m1) / 2`，反复迭代直到两次阈值之差小于 ΔT。
   - **大津法** `image_threshold_otsu()`：统计灰度直方图，遍历 0~255 每一个灰度级，计算
     `delta = w0*(u0-u)^2 + w1*(u1-u)^2`，取类间方差最大时对应的灰度值作为阈值。
2. **二值化** `image_binarize()`：灰度值 **大于** 阈值置为全白(255)，**小于等于** 阈值置为全黑(0)。

## 三、在例程中的使用

`user/main.c` 的摄像头帧处理部分：

```c
#if(1 == IMAGE_BINARIZE_ENABLE)
    image_threshold_calc(IMAGE_THRESHOLD_MODE);     // 1.求全局阈值
    image_binarize(image_copy[0]);                  // 2.二值化并写入发送缓冲区
    ...
#else
    memcpy(image_copy[0], mt9v03x_image[0], MT9V03X_IMAGE_SIZE);
#endif
```

二值化结果直接写进原来的 `image_copy` 发送缓冲区，**同时完成了原来的图像备份工作**，
所以不需要再申请一幅 120×188 的图像数组，不会额外占用 RAM。
调用 `seekfree_assistant_camera_send()` 之后，逐飞助手上显示的就是黑白二值化图像。

## 四、可调参数

在 `user/main.c` 中：

| 宏 | 默认值 | 说明 |
| --- | --- | --- |
| `IMAGE_BINARIZE_ENABLE` | 1 | 1：发送二值化图像；0：发送原始灰度图像 |
| `IMAGE_THRESHOLD_MODE` | `IMAGE_THRESHOLD_MODE_OTSU` | 阈值算法：大津法 / 迭代法 / 手动固定阈值 |
| `IMAGE_THRESHOLD_PRINT_FRAME` | 50 | 每多少帧通过 Debug 串口打印一次当前阈值，0 表示不打印 |

在 `code/image_process.h` 中：

| 宏 | 默认值 | 说明 |
| --- | --- | --- |
| `IMAGE_THRESHOLD_MANUAL` | 128 | **手动模式的固定阈值**，取自文章的 `#define Thres 128 //阈值`，范围 1~254 |
| `IMAGE_THRESHOLD_OFFSET` | 0 | **自动阈值的微调偏移**，范围 -100~100 |
| `IMAGE_MANUAL_COMPARE_AUTO` | 1 | 手动模式下顺便算出大津法阈值，串口同时打印两个值便于对比；确定阈值后可改 0 省运算 |
| `IMAGE_ITERATION_INIT` | 58 | 备用初始阈值（整幅图全黑/全白时兜底）；正常情况下初值取图像平均灰度 |
| `IMAGE_ITERATION_ERROR` | 2 | 迭代收敛误差 ΔT（对应文章 `ERROR`） |
| `IMAGE_OTSU_STEP` | 2 | 直方图抽样步长，2 表示隔行隔列取样（与文章一致），改 1 更精确但更慢 |
| `IMAGE_OTSU_EARLY_BREAK` | 1 | 类间方差开始减小时提前退出，加速用 |

### 想调整二值化阈值，改哪一个？

阈值是**每帧自动算出来**的，存在全局变量 `image_threshold` 里，`image_binarize()` 就是拿它做比较，
所以正常情况下没有"一个固定的阈值"可以调。想人为干预，用下面两种方式：

| 需求 | 改什么 | 怎么改 |
| --- | --- | --- |
| 整幅图想偏白一点 / 偏黑一点 | `IMAGE_THRESHOLD_OFFSET` | 正数=阈值变大=图像偏黑，负数=阈值变小=图像偏白 |
| 完全固定一个阈值，不做自动计算 | `IMAGE_THRESHOLD_MODE` 改成 `IMAGE_THRESHOLD_MODE_MANUAL`，再调 `IMAGE_THRESHOLD_MANUAL` | 适合光照固定的场地，省掉求阈值的运算时间 |

调试时把 `IMAGE_THRESHOLD_PRINT_FRAME` 改小（例如 1），串口就会每帧打印当前实际使用的阈值，
先看清楚自动阈值大概是多少，再决定手动值或者偏移量取多少。

> 注意：阈值变大 = 更多像素被判成**黑**（背景），阈值变小 = 更多像素被判成**白**（赛道）。
> 如果发现赛道被"吃掉"了，说明阈值偏大；如果背景大片变白，说明阈值偏小。

### 固定阈值（当前默认配置）

`user/main.c` 里 `IMAGE_THRESHOLD_MODE` 已设为 `IMAGE_THRESHOLD_MODE_MANUAL`，
固定阈值取 `image_process.h` 中的 `IMAGE_THRESHOLD_MANUAL`，当前为 **128**。

文章里出现的两个与二值化有关的数值：

| 文章中的定义 | 含义 | 是否可用作固定阈值 |
| --- | --- | --- |
| `#define Thres 128 //阈值` | 全局阈值 | **是**，当前就用这个值 |
| `float BlackThres = 58; //黑白阈值` | 迭代法的**初始**阈值，会被迭代不断更新 | 否，它不是最终阈值 |

**128 只是文章给的经验值，能不能直接用取决于你的曝光时间、增益和现场光照**，必须上车实测：

1. `IMAGE_MANUAL_COMPARE_AUTO` 保持 1，`IMAGE_THRESHOLD_PRINT_FRAME` 改成 1；
2. 把车放到赛道上，看 Debug 串口（115200）打印的 `threshold manual:128 auto:xxx`；
3. `auto` 就是大津法在你现场光照下算出来的阈值：
   - `auto` 和 128 差不多（差 10 以内）→ 128 可以直接用；
   - `auto` 明显比 128 小（例如 60，常见于光线偏暗）→ 把 `IMAGE_THRESHOLD_MANUAL` 改成 `auto` 附近的值；
   - `auto` 明显比 128 大（例如 160，常见于光线很亮）→ 同样改成 `auto` 附近的值；
4. 确定数值后把 `IMAGE_MANUAL_COMPARE_AUTO` 改回 0，省掉这部分运算。

> 固定阈值的优点是稳定、省运算时间；缺点是换场地/换光线就要重新标定。
> 如果比赛现场光照变化大，建议直接用大津法（`IMAGE_THRESHOLD_MODE_OTSU`）。

### 近端参考白点阈值（`IMAGE_THRESHOLD_MODE_NEAR_REF`，按逐飞直播的思路加的）

逐飞直播《搜线算法优化》第 1 条：**取最靠近车身那几行图像（一定全是赛道）的灰度均值，
作为"参考白点"，阈值按这个白点的比例取**。好处是换场地、换光线、镜头脏了、灯变了，
阈值自己跟着走，不用再手调固定值。

本工程的实现（`image_process.h` 里一组 `IMAGE_NEAR_REF_*` 宏）：

| 项 | 值 | 说明 |
| --- | --- | --- |
| 取样区 | 行 110~117，列 40~147 | **避开最下面两行** —— 实车发现第 119 行中心偶尔压着一小块暗斑，会把这个均值拉低 |
| 阈值 | `参考白点 × 0.62` | 赛道灰度约 235 → 阈值 146，和原来手调的 150 基本一致 |
| 平滑 | `IMAGE_NEAR_REF_SMOOTH = 1` | 阈值做一阶平滑（3:1），防止逐帧抖动 |
| 兜底 | `IMAGE_NEAR_REF_MIN = 100` | 取样区均值低于 100（摄像头被挡/全黑/车冲出赛道）就**保留上一次阈值**，不跟着跳 |
| 代价 | 8×108 = 864 个像素 | 每帧一次，可以忽略（对比：整幅快照是 22560 个像素） |

**怎么用（默认没打开，行为不变）**：

1. 先直接烧现在的固件，看 Debug 串口（115200）每隔 50 帧打印的一行：
   `th:150 auto:xxx ref:235 near:146 lost L:0 R:0`
   `ref` 就是参考白点，`near` 是按它算出来的阈值 —— 和现场的 `auto`（大津法）对一下；
2. 数值看着合适，就把 `image_process.h` 里的
   `#define IMAGE_THRESHOLD_MODE  IMAGE_THRESHOLD_MODE_MANUAL`
   改成 `IMAGE_THRESHOLD_MODE_NEAR_REF`，重新编译即可；
3. 换场地后不用再改数字，`ref` 会自己适应；如果发现赛道被吃掉/背景变白，
   调 `IMAGE_NEAR_REF_RATIO`（调大 = 阈值更高 = 图像更黑）。

> 三种模式的关系：`MANUAL` 最省时间（编译期常量参与比较）、`NEAR_REF` 自适应且仍然便宜、
> `OTSU`/迭代法每帧都要扫全图算直方图（我们把它降频到 10 帧一次了）。

## 五、与文章代码的差异（都已修正并加了保护）

1. **迭代法**：文章代码中 `S0/S1/N0/N1` 只在函数开头清了一次零，每轮迭代会把上一轮的数据继续
   累加进去，求出的均值会偏大；这里改成每轮迭代开始时重新统计。另外增加了 `N0` 或 `N1` 为 0
   （整幅图全黑/全白）时的除零保护，以及最大迭代次数限制，避免卡死在 `while` 里。
2. **大津法**：文章里 `gray_sum/pixelSum` 用的是整型除法，会丢掉小数，这里改成浮点除法；
   `pow(x,2)` 直接写成 `x*x`，结果相同但省掉了库函数调用。
3. **浮点比较**：迭代法中与像素比较的阈值先四舍五入成整型再比较，避免 2 万多次浮点比较拖慢帧率。
