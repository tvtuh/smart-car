## 一、为什么要推倒重写

实车跑下来，那套东西有三个硬伤：

| 硬伤 | 实车证据 |
| --- | --- |
| **角点检测是整条链里最不稳的一环** | 示波器 `ch5`/`ch6`（角点行号）时有时无；还抓到过 `ch5=62 / ch6=45`、`ch5=71 / ch6=36` —— "左上角点在左下角点**下面**"，物理上不可能 |
| **补线挂在状态机上** | `ch3` 在 1/0 之间抖 → 补线一开一关 → 边的形状每帧都在变 = **"线一直跳"** |
| **好几套机制抢着写同一组边线** | 十字补线 / 圆环补线 / 丢线插值 / 丢线贴边 各自为政，谁最后写谁算 |

顺带还有个性能问题：旧版每帧都要"逐列预扫线"（≈全图 2 万次读），纯浪费。

## 二、现在只剩一条链路

```c
void cross_road_process (uint8 *binary_image)
{
    // 1. 每帧算一遍"哪几行是横杠行"
    for (y = 0; y < 120; y++) cross_row_white[y] = cross_row_is_white(image, y);

    // 2. 状态：只看横杠在哪（只对外汇报，不驱动补线）
    if (找到横杠段 [top, bottom]) {
        cross_flag  = 1;
        cross_state = (bottom 已经到画面最下面) ? INSIDE : IN;
    } else {
        cross_flag = 0;
        cross_state = 刚消失 ? OUT（保持 15 帧）: NONE;
    }

    // 3. 补线：把"不可信的那一段"接过去（不依赖 state！）
    if (找到不可信段 [top, bottom]) cross_bridge_range(top, bottom);
}
```

### 2.1 横杠判据（从另一个工程借来的）

```c
// 某一行里 90% 以上的采样点是白 -> 这一行就是横杠行
static uint8 cross_row_is_white (uint8 *image, uint16 row)
```

- **为什么稳**：横杠"几乎整行是白"是**物理事实**，不需要任何阈值调参，
  也不会像"找白区拐角(角点)"那样被别的白区（亮地面、反光）骗；
- **为什么便宜**：抽样步长 6（一行 32 个点），非白行数够 10% 的非白点就**提前退出**；
- 参数：`CROSS_WHITE_PERCENT = 90`、`CROSS_WHITE_STEP = 6`、`CROSS_WHITE_MIN_ROWS = 3`。

### 2.2 补线：桥接（不猜边线）

横杠那一段左右边线**本来就不存在**，所以不猜它，直接用两端可靠的中线/半宽接过去：

```
不可信段 = [top, bottom]
near_y = top - 1     （段【上面】第一个行，靠远处）
far_y  = bottom + 1  （段【下面】第一个行，靠车身）

两端都有 -> 中线/半宽按行线性插值       ← 斜入十字时，中线自然朝【远赛道】对齐
只有一端 -> 用那一端【可靠侧】的趋势直线延伸
整段写完后 把两侧丢线标志清掉（不让后面的"丢线插值/贴边"再覆盖回来）
```

**两个踩过的坑（都写在代码注释里了）**：

1. **绝不用"保持上一行的值"**：实测一张帧里第 0~9 行三个数组数值完全一样，
   画面上就是**一根竖直线 + 上下两个折角**。凡是"没边线"的地方都要按趋势延伸。
2. **估趋势的方向不能写反**：丢线段贴着画面【最下面】时，可靠的一侧在【上面】(dir = -1)；
   贴【最上面】时相反。写反了**不会报错**，只会静默退化成"保持原值"。

### 2.3 "不可信行"的两种定义

| 用途 | 判据 |
| --- | --- |
| **状态**（对外汇报） | 只认"整行几乎全白" —— 这才是横杠 |
| **补线** | "整行几乎全白" **或** "两侧都丢线" |

补线多认一种，是因为边线真的跑出画面（赛道比视野宽）时也该按趋势接过去，
而不是每个机制各写一截。

## 三、和圆环模块的互斥

```c
// ring_road.c 里
if ((0 != cross_state) || (0 != cross_bridge_used)) return;   // 十字优先，圆环补线不做
```

实车抓到过"十字里 `ch4 = 23`（误判成右环且在环内）"——两套补线同时改边线，
线就会一帧一个形状。现在**十字在补线时，圆环一律不补**。

## 四、示波器怎么看

| 通道 | 含义 |
| --- | --- |
| `ch3` | 十字状态：0 不在 / 1 横杠在前面 / 2 横杠在车身下面 / 3 刚出十字 |
| `ch5` | **横杠段的【上】边界行**（0 = 这一帧没有横杠） |
| `ch6` | **横杠段的【下】边界行** |

> 注意：`ch5`/`ch6` 的含意变了。以前是"左上/左下 L 角点行号"，现在是**横杠段的上下边界行**——
> 这个信息更直接：`ch5=40 / ch6=85` 就是"横杠占第 40~85 行"。
> 一个好帧应该满足 `ch5 < ch6`，而且两者只随车前进平滑变化。

## 五、参数速查（`code/cross_road.h`）

| 宏 | 默认 | 说明 |
| --- | --- | --- |
| `CROSS_WHITE_PERCENT` | 90 | 一行里白点比例超过它才算横杠行。**调小** = 更容易算横杠（可能把亮地面算进去）；**调大** = 更严 |
| `CROSS_WHITE_STEP` | 6 | 抽样步长。调小更准更慢 |
| `CROSS_WHITE_MIN_ROWS` | 3 | 至少连续几行才算一段横杠（防空噪点） |
| `CROSS_BRIDGE_SLOPE_MAX` | 3 | 按趋势延伸时，每行最多变多少像素（防趋势被噪声带跑） |
| `CROSS_LOOK_BACK` | 6 | 估趋势时往回看几行 |
| `CROSS_OUT_HOLD` | 15 | 横杠消失后，`cross_state` 保持 OUT 多少帧再回 NONE |
