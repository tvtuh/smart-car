## 二、预扫线：逐列找白区

对 **x = 0 ~ 187** 每一列调用 `cross_scan_column(image, x, &up, &down)`。

### 2.1 三个判定函数

**① 白点校验 `cross_white_ok_up(image, y, x)`**

```c
if (像素(y,x) 不是白) return 0;
cnt = (y+1 白) + (y+2 白) + (y+3 白);
return (cnt >= 2);
```

即：**自己是白，且下面 3 行里至少 2 行是白**。

> **为什么不能只判"自己是白"**：白区顶部正下方如果有个孤立黑噪点（一行黑），
> 按"连续 N 个白点"的写法，真正的顶点就会被判掉，白区的上沿会往下退好几行。
> 仿真数据：改成多数校验后角点横向平均误差 **7.2 → 3.7 像素**，
> 误差 >15 像素的离群点 **8 个 → 0 个**。

**② 黑段校验 `cross_black_run_down(image, y, x)`**

```c
return 从 (y,x) 往下连续 3 个点都是黑;
```

> 同样是为了躲噪点：**一个孤立黑点不应该把白区切断**。

**③ 扫描循环**

```c
for (y = 0; y <= 120; y++)
{
    if (y < 120 && 白点校验(y,x) 成立)
    {
        if (start < 0) start = y;          // 白区开始
    }
    else if (y >= 120 || 黑段校验(y,x) 成立)
    {
        if (start >= 0) { 记录一段白区 [start, y-1]; start = -1; }
    }
    // 两个都不成立 → 孤立黑噪点 → 什么都不做，继续留在当前白区里
}
```

### 2.2 用 x=60 这一列逐步走一遍

先写出 x=60 这一列的像素（1=白 0=黑）：

```
行  0~19 : 0  0  0 ... 0        ← 远赛道在列 77~111，不含 60
行 20~55 : 1  1  1 ... 1        ← 横杠，全覆盖
行 56~59 : 0  0  0  0           ← 近赛道左边线在 61（行56 时），还没张到 60
行 60~119: 1  1  1 ... 1        ← 近赛道
```

扫描过程：

| y | 白点校验 | 黑段校验 | 动作 |
| --- | --- | --- | --- |
| 0~19 | 不成立 | **成立**（0,1,2 都黑） | start<0，什么都不做 |
| 20 | 成立 | — | `start = 20` |
| 21~55 | 成立 | — | 继续 |
| 56 | 不成立 | 成立（56,57,58 都黑） | **记录白区 [20, 55]**，`start = -1` |
| 57~59 | 不成立 | 成立 | 什么都不做 |
| 60 | 成立 | — | `start = 60` |
| 61~119 | 成立 | — | 继续 |
| 120（越界） | — | `y>=120` 成立 | **记录白区 [60, 119]** |

**结果：x=60 这一列收集到 2 段白区**

```
run_top[0]=20, run_bot[0]=55      ← 横杠
run_top[1]=60, run_bot[1]=119     ← 近赛道
n = 2
```

### 2.3 合并间隔很小的白区（`CROSS_MERGE_GAP = 6`）

```c
for (i = 1; i < n; i++)
{
    if ((run_top[i] - run_bot[i-1] - 1) <= 6)     // 间隔行数
    {
        run_bot[i-1] = run_bot[i];                // 合并到前一段
        后面的段整体前移;  n--;  i--;
    }
}
```

x=60 的情况：

```
间隔 = run_top[1] - run_bot[0] - 1 = 60 - 55 - 1 = 4  ≤ 6  → 合并！
合并后：run_top[0]=20, run_bot[0]=119,  n=1
```

**为什么必须合并** —— 看下一步就明白了。

### 2.4 选"离图像中间行最近的一段"

```c
CROSS_CENTER_ROW = 60     // 图像中间行

对每一段：
    如果 段包含行 60              → 距离 = 0
    如果 段整体在行 60 上方       → 距离 = 60 - 段的下沿
    如果 段整体在行 60 下方       → 距离 = 段的上沿 - 60 + CROSS_UP_BIAS(10)
选距离最小的那一段
```

**不合并会怎样**（这是实车暴露的 bug）：

| | 段 | 距离计算 | 距离 |
| --- | --- | --- | --- |
| 不合并 | 横杠 [20,55] | 在 60 上方 → 60-55 = 5 | 5 |
| 不合并 | 近赛道 [60,119] | 包含 60 → 0 | **0 ← 被选中** ✗ |
| 合并后 | [20,119] | 包含 60 → 0 | **0 ← 被选中** ✓ |

**不合并的后果**：

```
up_y[60] = 60   （近赛道的上沿）
而真实应该是 up_y[60] = 20   （横杠的上沿）
```

→ 角点检测会在这里找到一个**假角点 (66, 60)**（真实是 (77, 20)）
→ 补线范围变成 [55, 60] 只有 5 行 → **等于没补** ✗✗

**合并后**：`up_y[60] = 20` ✓，角点变成 (82,20)（真实 77,20）✓

## 三、找四个 L 角点

### 3.1 扫描规则

```c
cross_find_corner(曲线, 从左往右?, 找变大?, 角点下标)

左上: cross_up_y,   从左往右, 找变小 → 下标 0
右上: cross_up_y,   从右往左, 找变小 → 下标 1
左下: cross_down_y, 从左往右, 找变大 → 下标 2
右下: cross_down_y, 从右往左, 找变大 → 下标 3
```

### 3.2 "参考高度"怎么取（关键技巧）

```c
back = (从左往右扫) ? (x - CROSS_REF_BACK) : (x + CROSS_REF_BACK);   // BACK = 6

if (back 在范围内 && 曲线的 back 处有效)
    ref = 曲线[back];                  // ★ 用 6 列之前的值当参考
else if (ref 还没设过 && 曲线的 x 处有效)
    ref = 曲线[x];
```

**为什么要取 6 列之前，而不比较相邻两列**：

```
up_y 从 20 降到 0，实际是分散在几列里慢慢降的：

x    :  74   75   76   77   78   79   80
up_y :  20   20   19   14   10    5    0
                    ↑
相邻两列比较：19→14 差 5，14→10 差 4，10→5 差 5，5→0 差 5
             每次都小于容差 8  → 永远触发不了 ✗

取 6 列之前：
x=80: ref = up_y[74] = 20, cur = up_y[80] = 0
      20 - 0 = 20 > 8  → 触发 ✓
```

**角点的纵坐标取 `ref`（突变前的值）而不是 `cur`**：

```c
cross_corner_y[index] = (uint8)ref;
```

这样上角点的 y = **横杠顶行（20）**，而不是远赛道顶部（0）✓
正是补线需要的高度。

### 3.3 x=80 处的实际计算

```
x=80 处：
  back = 80 - 6 = 74
  ref  = up_y[74] = 20          （有效）
  cur  = up_y[80] = 0
  0 < 20 - 8 = 12  → 触发！

  cross_corner_x[0]     = 80
  cross_corner_y[0]     = 20      ← 取 ref
  cross_corner_valid[0] = 1
```

### 3.4 四个角点结果

| 角点 | 检测位置 | 理论位置 | 误差 |
| --- | --- | --- | --- |
| 左上 | (80, 20) | (77, 20) | 3 像素 |
| 右上 | (106, 20) | (111, 20) | 5 像素 |
| 左下 | (61, 55) | (61, 55) | 0 |
| 右下 | (128, 55) | (127, 55) | 1 |

> 上角点的横向误差来自"参考高度取了 6 列之前"这个系统性偏移 —— 这是**已知的取舍**：
> 不取的话角点根本找不到，取了的话横向差几个像素。

### 3.5 有效性过滤 + 记忆

```c
// 纵坐标超出 [5, 110] 的作废
if (corner_y[i] < 5 || corner_y[i] > 110) valid[i] = 0;

// 上方两个角点都在 → 记下来给状态2用
if (valid[0] && valid[1])
{
    cross_last_x[0] = corner_x[0];   cross_last_y[0] = corner_y[0];
    cross_last_x[1] = corner_x[1];   cross_last_y[1] = corner_y[1];
    cross_last_valid[0] = cross_last_valid[1] = 1;
}
```

#### 3.5.1 角点自洽检查（**实车：动起来线一直跳**）

示波器上抓到过这样的组合：

| 图 | ch5（左上角点行） | ch6（左下角点行） | 问题 |
| --- | --- | --- | --- |
| 1 | 62 | 45 | 左上角点在左下角点**下面** ✗ |
| 2 | 41 | 101 | 正常 ✓ |
| 3 | 71 | 36 | 同上 ✗ |

"左上角点在左下角点下面"物理上不可能（横杠的上沿一定在下沿上面）。
这种帧里补线就是拿两个假角点连直线 → **中线一跳一跳**，就是实车描述的
"十字里有时候能补齐，但一动线就一直跳"。

加了两条不需要调参的硬检查（不满足就把那一侧的角点作废）：

```c
① 同一侧：上角点的行号必须小于下角点            // 左上 < 左下、右上 < 右下
② 左角点在画面中线(94)左边、右角点在右边          // 容差 CROSS_CORNER_SIDE_TOL = 25
```

第 ② 条同时能挡住"把地面/别的白区当成角点"那种假角点
（实车出现过"右下角点"在第 59 列、而右边线在第 160 列，差了 100 像素）。

#### 3.5.2 角点记忆（治"补线一会儿有一会儿没有"）

只做自洽检查的话，角点会"这一帧有效、下一帧作废"来回切，补线跟着一补一停，
看起来还是跳。所以再加一层记忆：

```c
每个角点各自记：这一帧有效 -> 刷新自己的记忆
                这一帧无效 -> 自己的年龄++；年龄 <= CROSS_CORNER_MEMORY(15) 就用记忆顶上
```

> 注意是**每个角点各自记**，不是"四个都自洽才记" —— 四个同时凑齐很难，
> 那样记忆经常是空的、缺角点时补不上（实车示波器上就是 `ch5=0` / `ch6=0` 交替出现）。

### 3.6 补线方式 2：桥接中线（`CROSS_FIX_MODE = 2`，当前默认）

**为什么不再用角点**：角点检测是整条链里最不稳的一环（实车 `ch5`/`ch6` 时有时无）。
而"横杠那一段两侧都没有边线"这件事本身非常可靠——它就是一个 `track_lost` 的标志位，
不需要任何阈值判断。所以：

```
1. 找最长的一段"两侧都没找到边线(0x03)"的行  ->  这就是横杠那一段 [a, b]
2. 两端各取一个可靠行：近端 = a-1、远端 = b+1，算出它们的中线和半宽
3. 横杠段每一行：
     中线 = 两端中线按行线性插值     半宽 = 两端半宽按行线性插值
     左 = 中线 - 半宽     右 = 中线 + 半宽     中线 = (左+右)/2
   只有一端可用（车已经整个在十字里）：用那一端附近 6 行的趋势【直线延伸】
4. 写完把这一段的两侧丢线标志清掉
   —— 不清的话，后面的 `track_fill_lost_side` 会用"只有一端有效就保持原值"覆盖回来，
      而"保持原值"正是实测里"第 0~9 行数值完全一样、画面上竖直一段+折角"的来源
```

**实测数据（一张十字里的帧，逐行量出来的中线）**：

| 行 | 绿 | 红 | 黄 | 宽度 |
| --- | --- | --- | --- | --- |
| 119 | 17 | 92 | 167 | 150 |
| 60 | 48 | 100 | 149 | 101 |
| 16 | 16 | 91 | 164 | 148 |
| **0~9** | **39** | **103** | **167** | **128（9 行完全一样 = 保持出来的）** |

**斜入十字时会不会走偏**：不会。桥接的两端是"近赛道中线"和"远赛道中线"，
斜入时中线的出口方向由**远赛道**决定 —— 也就是路的方向，车自己就修正了。
（对比之下，"把中线锁死不动"才会走偏，因为锁死等于保持进十字前的转向。）

**开关**：`cross_road.h` 的 `CROSS_FIX_MODE`（1 = 连角点，2 = 桥接中线）；
另外代码里有个运行期变量 `cross_use_corner_fix`，置 1 可以临时切回连角点那套做对比。

## 四、估计横杠下沿（`cross_estimate_bar`）

```c
cross_bar_bottom = CROSS_Y_NONE;
if (上角点不全) return;                      // 估不出来

for (x = 0; x < 188; x++)
{
    if (x 在两个上角点之间) continue;         // 远赛道所在的列 跳过
    if (cross_down_y[x] == NONE) continue;
    cross_bar_vals[n++] = cross_down_y[x];
}
if (n < 8) return;                           // 有效列太少 不敢估
插入排序;
cross_bar_bottom = cross_bar_vals[n / 2];    // 中位数
```

用示例数据：

```
上角点 x 范围 = [80, 106]  → 这些列跳过
剩下的列：0~79 和 107~187
它们的 down_y：前面是 55（只有横杠），后面也是 55
中位数 = 55   ✓ 正好是横杠下沿
```

**为什么要它**：横杠区域里寻线**能"找到"一条边** —— 那是**横杠的边**，
不是赛道的边，所以**那些行不会被标记成丢线** ✗

补线如果只补丢线的行，就会**漏掉这一整段** → 斜入十字时画出来断断续续的。
有了 `cross_bar_bottom`，补线就能"**无条件覆盖到横杠下沿**" ✓

## 五、五个预识别条件（逐个算给你看）

### 条件 1a：丢线总数

```c
if (track_left_lost_count + track_right_lost_count < CROSS_LOST_SUM_MIN) return 0;
```

示例：`36 + 36 = 72 ≥ 30` ✓ 通过

### 条件 1b：至少要有一侧丢得多

```c
if (track_left_lost_count < CROSS_LOST_MIN && track_right_lost_count < CROSS_LOST_MIN) return 0;
```

示例：`36 ≥ 15` ✓ 通过

> **为什么是"至少一侧"而不是"两侧都"**：
> 斜入十字时横杠在图像里是**斜的**，一侧丢得多、另一侧丢得很少。
> 实车帧实测 **左 72 行 / 右 4 行** —— 要求两侧都 ≥15 的话这一帧永远不通过 ✗

### 条件 1.5：同时丢线的行数

```c
overlap = 0;
for (y = 0; y < 120; y++)
    if ((track_lost[y] & 0x03) == 0x03) overlap++;
if (overlap < CROSS_OVERLAP_MIN) return 0;
```

示例：行 20~55 同时丢 → `overlap = 36 ≥ 3` ✓ 通过

> **这一条是区分圆环的关键**：十字的横杠把左右**同时**盖住；
> 圆环入口只有一侧道路张开，另一侧是直道。
> 实车实测：右环入口重叠 **0 行**（左丢0/右丢56），正入十字 **39 行**，斜入 **29 行**。

### 条件 3：中间区域存在"几乎全白"的一行

```c
max_white = 0;
for (y = 24; y <= 96; y++)                   // CROSS_BAND_Y1 ~ Y2
{
    white_count = 这一行里白点的个数;
    if (white_count > max_white) max_white = white_count;
    if (max_white >= 150) break;              // 够白了 不用再扫
}
if (max_white < 150) return 0;
```

示例：行 20~55 每一行都是 188 个白点 → `max_white = 188 ≥ 150` ✓ 通过

> **为什么要扫一整段行而不是只看中间那一行**：
> 前瞻较远时整条横杠会落在中间行**上方**（实车图就是这样），
> 只看中间行的话这一条永远不成立，**十字根本识别不出来** ✗

### 条件 4：中心矩形内白点够多

```c
white_count = 0;
for (y = 40; y <= 85; y++)
    for (x = 60; x <= 128; x++)
        if (白) white_count++;
if (white_count < 2000) return 0;
```

示例：`(85-40+1) × (128-60+1) = 46 × 69 = 3174` 个位置，几乎全是白
→ `white_count ≈ 3100 ≥ 2000` ✓ 通过

> 作用是防止和三岔、急弯混淆。

### 条件 5（在状态机里）：远端两个角点都在

```c
up_ok = (valid[0] && valid[1]);
if (pre_ok && up_ok) → 进入十字状态
```

示例：左上 (80,20) 和右上 (106,20) 都有效 → `up_ok = 1` ✓

**五个条件全部通过 → `cross_state` 从 `NONE(0)` 变成 `IN(1)`** ✓

## 六、状态机怎么推进

```c
switch (cross_state)
{
    case NONE:                       // 不在十字
        if (预识别通过 && 上角点都在) {
            连续帧计数++；
            连续 CROSS_ENTER_CONFIRM(3) 帧都满足 → IN      // ★ 防误判 1
        } else {
            连续帧计数 = 0;
        }
        break;

    case IN:                         // 正在进入
        if (连着 CROSS_IN_FAIL_MAX(6) 帧都看不到横杠) → NONE（假十字，立刻复位）  // ★ 防误判 2
        cross_fix_line(IN);          // ★ 补线
        if (上角点消失) → INSIDE
        break;

    case INSIDE:                     // 车头完全在十字内
        cross_fix_line(INSIDE);      // ★ 补线（用记忆角点）
        if (上角点又出现) → OUT
        break;

    case OUT:                        // 正在出十字
        cross_fix_line(OUT);         // ★ 补线
        if (上角点再次消失) → NONE
        break;
}

// 状态保护
if (state != NONE) { count++; if (count > 150) → NONE; }
```

**四个状态对应车的四个位置**：

```
     NONE          IN           INSIDE          OUT          NONE
  ────────────┬──────────┬──────────────┬──────────┬────────────
   还没到十字   正在进入    车头在十字内    正在出去    已经出去
              角点都在    角点消失        角点又出现   角点再消失
```

**为什么 `INSIDE` 时角点"又出现"算作 OUT**：车头进十字时，
远赛道被车头挡住/移出视野，所以上角点消失；
等到车快出去时，**远方的赛道又重新进入视野** → 上角点又出现 ✓

### 6.1 两个防误判（实车事故：假十字卡住 10 秒）

**现象**：车放在车库地面上不动，画面里根本没有十字，但示波器 `ch3`（十字状态）一直是 **1**；
右边线在十几行里斜着扎到左边去（见 7.1 的实车数据），**过大约 10 秒自己又恢复正常**。

**原因**：原来状态 `IN` 唯一的出口是"远端两个角点消失"。车库里左边地面反光很亮（灰度 > 150），
预扫把地面也当成白区，凑出一对假的远端角点；车不动，这对角点就一直在，
状态就一直卡在 `IN`，只能等 `CROSS_STATE_TIMEOUT = 150 帧 ≈ 10 秒` 强制复位。

**改法**（两处，都不扫图像、不花时间）：

| 防误判 | 位置 | 做什么 |
| --- | --- | --- |
| ① 进十字要"连续确认" | `NONE → IN` | 连续 `CROSS_ENTER_CONFIRM`(3) 帧都满足条件才进。放车、挥手、过坎这种一两帧的画面剧变骗不进去了 |
| ② 进去之后要"复查横杠" | `IN` 状态内 | 每帧用**丢线计数**（预识别条件 1a/1b/1.5，纯计数器）复查横杠还在不在；连着 `CROSS_IN_FAIL_MAX`(6) 帧看不到 → 判定假十字，**立刻复位**（约 0.4 秒，而不是 10 秒） |

为什么复查用丢线计数就够了：**真十字的特征很硬 —— 横杠把边线盖住，丢线数一定很多**；
假十字（画面里没有横杠）丢线数马上就掉下来了。所以"丢线数掉下来"就是最便宜、最可靠的"看错了"信号。

> 注意：复查只在 `IN` 状态做。`INSIDE`/`OUT` 时车已经在十字上/出十字，
> 丢线数本来就可能不高，在那里复查会把真十字误退出。

## 七、补线：`cross_fix_line` → `cross_fix_side`（左右各一次）

```c
static void cross_fix_line (uint8 state)
{
    uint8 use_memory = (state == CROSS_STATE_IN) ? 0 : 1;
    cross_fix_side(0, 0, 2, use_memory);     // 左侧：用左上+左下角点
    cross_fix_side(1, 1, 3, use_memory);     // 右侧：用右上+右下角点
}
```

`cross_fix_side(side, up_index, down_index, use_memory)` 内部：

### 方式 A：上下角点都在 → 直接连直线

```c
if (up_valid && down_valid)
{
    cross_fill_between(edge, 上角点y, 上角点x, 下角点y, 下角点x);
    return;
}
```

`cross_fill_between` 做的事（**逐行线性插值**）：

```c
if (y1 > y2) { 交换两点 }                    // 保证 y1 <= y2

for (y = y1; y <= y2; y++)
{
    value = x1 + (x2 - x1) * (y - y1) / (y2 - y1);
    限幅到 [0, 187];
    edge[y] = value;
}
```

**用示例数据（左线）**：

```
上角点 (80, 20)，下角点 (61, 55)

y=20 : 61 那边... 等等，x1 = 80（上角点的列），x2 = 61（下角点的列）
y=20 : value = 80 + (61-80)*(20-20)/(55-20) = 80
y=30 : value = 80 + (-19)*(10)/35          = 80 - 5.4 = 74
y=40 : value = 80 + (-19)*(20)/35          = 80 - 10.9 = 69
y=55 : value = 80 + (-19)*(35)/35          = 61

→ track_left[20..55] = 80, 77, 74, ..., 61    一条斜线 ✓
```

**这条斜线就是"被横杠盖住的那段左边线"** ✓

#### 方式 A 的兜底加了「物理合理性检查」（实车事故）

`cross_fill_between` 是**整个十字补线里唯一没有斜率限制**的一条路
（方式 A 的两段拟合、方式 B 的最小二乘，算出来的 k 都被 `CROSS_SLOPE_MAX = 3.0` 卡住了）。
所以只要两个 L 角点里有一个是假的，它就会老老实实画出一条离谱的斜线。

**实车事故（车库里，左边地面大片反光、灰度超过阈值 150）**：

- 预扫线把左边那一大片亮地面也当成白区，在地面边缘扫出一个**假的「右下 L 角点」**；
- 于是右边界被这条两点直线从 (第 57 行, 第 161 列) 一路连到 (第 69 行, 第 59 列)；
- 画面上右边线在十几行里斜着扎到左边线旁边（那里右边界离左边界只剩 6 像素），中线跟着歪；
- 而十字状态机要等 `CROSS_STATE_TIMEOUT`(150 帧 ≈ 10 秒) 才强制复位，
  所以表现出来是「**刚把车放上去不对、不动它过一会儿自己又好了**」。

从两张截图里逐行量出来的数据（同一位置，两张图的图像内容完全一致）：

| 行 | 正常时右边界 | 出事时右边界 |
| --- | --- | --- |
| 57 | 167 | 161 |
| 58 | 166 | 152 |
| 62 | 162 | 115 |
| 66 | 160 | 77 |
| 69 | 160 | **59** |
| 70 | 159 | 159 ✓ |

**现在的检查**（不通过就**这一侧不补**，宁可保持寻线原来的结果）：

```c
① |x_down - x_up| <= CROSS_SLOPE_MAX * |y_down - y_up|     // 比拟合允许的斜率还斜 -> 角点一定是错的
② 补出来的每一行离对面边线 >= CROSS_FILL_MIN_WIDTH (20)    // 补到对面边线上了 -> 角点一定是错的
```

上面那组假角点：(dy = 12, dx = 102)，102 > 3.0×12 = 36 → 第 ① 条就把它挡掉了 ✓
真实十字的角点（例如 dy = 59, dx = 20 → 斜率 0.34）和赛道宽度（这里约 100 像素）都能通过 ✓

### 方式 B：只有上角点 → 最小二乘拟合 + 往下延长

```c
if (!up_valid)
{
    if (!use_memory) return;              // 状态1不允许用记忆值
    if (!cross_last_valid[side]) return;
    up_y = cross_last_y[side];            // 用记住的角点高度
}

if (!cross_fit_line(edge, lost_mask, up_y, &k, &b))
{
    // ★ 兜底：拟合点数不够 → 用"角点 + 上方最近有效点"两点连线
    ... 见下 ...
}
```

**`cross_fit_line` 的细节**：

```c
// 从角点上方开始 往上取 CROSS_FIT_ROWS(10) 行
for (y = from_y - 1; (y >= 0) && (n < 10); y--)
{
    if (这一行丢了线) continue;            // 丢线行不参与拟合
    sx += edge[y];  sy += y;
    sxy += edge[y]*y;  syy += y*y;
    n++;
}

if (n < CROSS_FIT_MIN_POINT(4)) return 0;    // 点太少

den = n*syy - sy*sy;
if (den ≈ 0) return 0;                       // 所有点在同一行

k = (n*sxy - sx*sy) / den;                   // 斜率
b = (sx - k*sy) / n;                         // 截距

// ★ 斜率限幅（文章特别强调）
if (k >  3.0) k =  3.0;
if (k < -3.0) k = -3.0;
if (|k| < 0.2 && k != 0) k = ±0.2;           // 十字补线不可能很平缓
```

> **为什么必须限幅**：文章的第二个注意事项 ——
> "必须限制斜率绝对值的范围，否则补线会严重且致命地抖动"。
> 因为最小二乘对离群点很敏感，几个噪点就能让斜率算到 ±10，
> 那条线补下去会横跨整个图像 ✗

**兜底逻辑**（这是我加的，实车图上"一截竖线"就是缺了它）：

```c
fit_ok = 0;
for (y = up_y - 1; y >= 0; y--)
{
    if (丢线) continue;
    if (up_y != y)
    {
        k = (edge[up_y] - edge[y]) / (up_y - y);      // 两点确定斜率
        限幅;
        b = edge[up_y] - k * up_y;
        fit_ok = 1;
    }
    break;                                            // 只用最近的那一个点
}
if (!fit_ok) return;                                  // 实在没辙才放弃
```

**最后往下补**：

```c
if (cross_bar_bottom != NONE)
    cross_fill_fit(edge, 0, up_y, cross_bar_bottom, k, b);         // ★ 无条件覆盖
else
    cross_fill_fit(edge, lost_mask, up_y, 119, k, b);              // 退回只补丢线行
```

`cross_fill_fit` 的 `lost_mask` 参数：

```c
// lost_mask 传 0 → 无条件覆盖
if ((lost_mask != 0) && (这一行没丢线)) continue;
value = k*y + b;
限幅;
edge[y] = value;
```

> **为什么传 0（无条件覆盖）**：横杠区域里寻线会找到**横杠自己的边**，
> 那些行**没有被标记成丢线**。只补丢线行的话就会漏掉一整段 ✗

## 八、完整时间线（车开过十字的全过程）

```
帧 1~N    状态 NONE
          预识别不通过（丢线不够）→ 不补线

帧 N+1    上角点出现 + 预识别通过
          → cross_state = IN，cross_flag = 1

帧 N+1~M  状态 IN
          up_ok = 1（上角点还在）
          补线：方式 A（上下角点都在）→ 连直线
          画面上：横杠区域出现一条完整斜线 ✓

帧 M+1    车头进入十字 → 上角点消失（远赛道被挡住/出视野）
          → cross_state = INSIDE，cross_flag = 0

帧 M+1~K  状态 INSIDE
          up_ok = 0
          补线：方式 B，用 cross_last_* 记住的角点 + 最小二乘拟合
          画面上：斜线继续维持 ✓

帧 K+1    车快出去 → 远赛道重新进入视野 → 上角点又出现
          → cross_state = OUT，cross_flag = 1

帧 K+1~P  状态 OUT
          补线：看角点情况，左右分别判断（一侧连直线、一侧拟合）

帧 P+1    上角点再次消失（车完全出去）
          → cross_state = NONE

任何时刻 如果连续 150 帧没推进 → 强制回 NONE（防卡死）
```

## 九、调试通道

| 通道 | 含义 |
| --- | --- |
| `ch3` | 十字状态：0=不在 1=进入 2=十字内 3=出十字 |
| **`ch5`** | **左上角点所在行**（0 = 没找到） |
| **`ch6`** | **左下角点所在行**（0 = 没找到） |

**补线的行范围就是 `[ch5, ch6]`** —— 如果某一段边线没被补上，
先看这两个数是不是覆盖了那一段：

| 现象 | 原因 |
| --- | --- |
| `ch5 = 0` | 左上角点没找到 → 角点检测问题（`CROSS_CORNER_TOL` 或曲线形状） |

| `ch5/ch6` 都有但范围太窄 | 横杠下沿估错，或角点行号不对 |
| `ch5/ch6` 都正常但线还是不对 | 拟合斜率或锚点的问题 |
